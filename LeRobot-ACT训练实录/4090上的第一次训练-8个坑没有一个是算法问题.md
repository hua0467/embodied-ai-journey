## 1. 为什么是今天：补齐三段链路的最后一段

我负责的链条是：采数据 → 转格式 → 喂模型训练。

前两段我很熟。VR 遥操、真机录制、转 LeRobot 格式，都是亲手做的。但第三段"训练"，一直是别人在做。

有个问题一直悬着：**没亲手跑通过训练，我对"数据该怎么采"的理解就是二手的。** 格式该长什么样、质量该到什么程度，都是别人告诉我的。这就像整车厂的人从没下过车间——对装配公差的理解，永远隔着一层。

公司把一台 48GB 显存的 RTX 4090 主机交到我手上，归我负责。我给自己定了一个很小的目标：**在这台机器上，独立完成一次完整的机器人策略训练。**

先用官方示例数据跑通链路，下一步换成我自己采的真机数据。

## 2. 从裸机开始：计划四步，走出一身泥

机器是 Ubuntu 22.04，CUDA 13.2 驱动。计划就四步：装 conda → 装 PyTorch → 装 LeRobot → 下数据集。

第一步就摔了。

装完 Miniforge3，终端输入 `conda`——command not found。我的第一反应是怀疑装错了，反复确认安装日志。查了半天：PATH 没配。后来证明，这一跤摔得很典型——**今天所有的问题都长这样：看着像大问题，实际全是小螺丝没拧紧。**

配完 PATH，PyTorch 装得很顺，`torch.cuda.is_available()` 返回 True。这时候我还以为后面的路好走了。

## 3. 8 个坑，没有一个是算法问题

结果从装 LeRobot 开始，坑一个接一个。按顺序：

**坑 1：conda 命令找不到。** PATH 没配。`conda init bash` + 重开 shell 解决。教训：装完环境工具的最后一步永远是 init。

**坑 2：pip 装的 lerobot 没有训练脚本。** 这个坑有点意思。pip 成品包只装库文件，训练脚本在源码仓库的 `src/lerobot/scripts/` 里。成品包像 4S 店的保养手册，只教你换机油；你想动 ECU，得看电路图——**源码仓库才是电路图。** 改成源码安装解决。

**坑 3：源码主分支要求 Python ≥ 3.12。** 我的环境是 3.10。clone 完先看 pyproject.toml 的 requires-python 这条经验，就是这么来的——不匹配，找历史 tag：`git checkout v0.4.4`。

**坑 4：训练脚本模块名不对。** 我按惯性写了 `python -m lerobot.scripts.train`，报模块不存在。真实名字是 `lerobot.scripts.lerobot_train`，用 `--help` 查出来的。这种坑最气人：方向完全对，只是名字猜错了。

**坑 5：训练一结束默认把模型推到 HuggingFace Hub。** 报错 `policy.repo_id argument missing`。原来 `push_to_hub` 默认是 True——像行车记录仪默认把视频传云端，我还没同意，它先伸手问我要账号。显式加 `--policy.push_to_hub=false`。

**坑 6：缺 gym-aloha。** `env.type=aloha` 即使只用数据集，仿真包的注册也发生在导入期。`pip install gym-aloha` 解决。

**坑 7：ResNet18 预训练权重下载 SSL 失败。** 训练机网络受限是常态。手动下载 45MB 权重放进 `~/.cache/torch/hub/checkpoints/`。这条直接改了我的工作习惯：**权重、模型、数据集，全部提前备离线副本**——就像进口件可能断供，仓库里得先有库存。

**坑 8：默认视频解码器报缺 FFmpeg 库。** torchcodec 依赖系统的 `libavutil.so.60` 等共享库，这台机器没有。加 `--dataset.video_backend=pyav` 解决。

八个坑，八种报错，八个解法。复盘的时候有个感受很真实：**这 8 个问题没有一个是算法问题，全是环境、版本、路径、默认参数。** 训练链路能不能跑通，瓶颈从来不在模型，在工程细节。而工程细节，恰好是愿意动手的人才能攒下来的东西。

## 4. 训练结果：2000 步的答卷

先 10 步验证链路，再 500 步，最后 2000 步。最终命令：

```bash
WANDB_MODE=disabled python -m lerobot.scripts.lerobot_train \
  --policy.type=act \
  --env.type=aloha \
  --dataset.repo_id=~/lerobot_data/aloha_sim_insertion_human \
  --policy.device=cuda \
  --policy.push_to_hub=false \
  --dataset.video_backend=pyav \
  --output_dir=~/lerobot_output/act_test_2000 \
  --steps=2000
```

2000 步，80 秒，约 25 step/s。loss 变化：

| step | loss |
|---|---|
| 200 | 7.315 |
| 400 | 3.047 |
| 600 | 2.502 |
| 800 | 2.209 |
| 1000 | 2.000 |
| 1200 | 1.803 |
| 1400 | 1.648 |
| 1600 | 1.492 |
| 1800 | 1.380 |
| 2000 | 1.266 |

loss 单调下降、没有振荡，像磨合期的油耗曲线——数字还高，但方向是对的。

1.27 离收敛还远，2000 步只是热身。但这不重要。重要的是：**checkpoint 正常落盘，训练、保存的整条机制在我手上是通的。**

另外两个数字：模型参数量 5161 万（约 52M），对单机后训练非常友好；25 step/s 意味着 5 万步约 33 分钟——正式训练以数万步计，这台机器完全扛得住。

## 5. 今日教训清单

| # | 教训 | 代价 |
|---|---|---|
| 1 | 装完环境工具的最后一步永远是 init + 重开 shell | command not found 白查半天 |
| 2 | 要跑官方脚本的项目，直接源码安装 | pip 成品包白装一轮 |
| 3 | clone 完先看 requires-python，不匹配就找历史 tag | 版本不兼容白折腾 |
| 4 | 不确定入口模块，`ls src/` 或 `--help` 最直接 | 模块名猜错报错一次 |
| 5 | 带联网动作的默认参数，优先显式关掉 | push_to_hub 报错一次 |
| 6 | 权重、模型、数据集提前备离线副本 | SSL 下载失败卡住训练 |
| 7 | 视频解码后端是高频坑，pyav 更省心 | torchcodec 报错一次 |
| 8 | 工程细节才是训练链路的真实瓶颈 | 全天 8 坑，无一算法 |
