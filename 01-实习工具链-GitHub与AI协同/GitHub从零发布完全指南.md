## 第零步：先检查一下你要发的东西安全吗

GitHub 公开仓库 = 全世界都能看。在你点发布之前，对一遍这个清单：

| 检查项 | 
|--------|
| 公司真实名称 → 换成「一家具身智能创业公司」之类的泛称 |
| 公司地址/办公地点 → 删掉 |
| 产品具体型号/内部代号 → 删掉 |
| 融资信息 → 删掉 |
| 客户/合作伙伴 → 删掉 |
| 同事和老板真名 → 删掉 |
| 内部项目名/文档标题 → 删掉 |
| 签了 NDA 的内容 → 绝对不能出现 |
| 照片里的公司 Logo/工牌/办公室 → 裁掉或打码 |

> 一个原则：拿不准的，先删。你永远可以以后再补，但泄出去的东西收不回来。

## GitHub 到底是什么（用人话版）

就是一个**网盘 + 个人主页**。你把文件传上去，别人打开你的主页就能看到。

几个你会遇到的词：

- **仓库（Repo）**：一个项目文件夹。你传上去的那个东西。
- **README.md**：仓库首页自动展示的介绍。别人点进你的仓库第一眼看到的就是它。**这是你的门面。**
- **Commit**：保存。每次改了东西点保存 = 一个 commit。
- **Star**：点赞收藏。别人觉得你的东西不错就点一下。
- **Fork**：别人把你的仓库复制一份到自己名下。

不用学 Git 命令。网页版点点按钮就够了。我到现在也没用过命令行——全在网页上搞的。

## 建仓库

1. 打开 [github.com](https://github.com)，登录
2. 右上角那个 **「+」** → 点它 → **「New repository」**
3. 填这些东西：

| 填什么 | 写什么 |
|--------|--------|
| Repository name | 英文小写 + 横杠连接，比如 `my-internship-notes` |
| Description | 一句话介绍，比如「一个贪玩的汽车人误入具身智能的实习记录」 |
| Public / Private | **公开**选 Public，**私人日志**选 Private |
| Add a README file | ✅ 勾上 |

4. 其他别管。点绿色 **「Create repository」** 按钮。

这就是你的仓库了。现在里面只有一个空的 README.md。

---

## 把写好的 README 传上去

1. 在仓库页面点 `README.md` 文件名
2. 点右上角**铅笔图标** ✏️
3. `Ctrl + A` 全选 → Delete 清空 → 把你本地写好的内容 `Ctrl + V` 粘贴进去
4. 页面底部 **Commit changes** 区域：
   - 第一行写一句说明（比如「更新自我介绍」）
   - 下面不用填
   - 选中 **Commit directly to the main branch**
5. 点绿色按钮

搞定。回仓库首页刷新，你的 README 就在上面了。

---

## 加更多文件

1. 仓库首页 → **Add file** → **Upload files**
2. 把文件拖进去
3. 底部写 commit message → 点 Commit

## 让仓库看起来像回事

### 加标签（Topics）

仓库首页右边 **About** 区域 → 点齿轮 ⚙️ → Topics 里输入标签，每输一个按回车。比如：`embodied-ai`、`robotics`、`llm`、`internship`、`learning-notes`。

加标签之后别人在 GitHub 上搜索时更容易找到你。

## 私有仓库 + 公开仓库

实习期间建议同时维护两个仓库：

| | 私有仓库 | 公开仓库 |
|---|---------|---------|
| 用途 | 脱敏前的原始日志、内部项目细节 | 脱敏后的学习笔记、可复用教程 |
| 可见性 | 只有你（和协作者） | 全世界 |
| 内容 | 公司信息、未脱敏数据、内部文档 | 技术方法论、踩坑经验、通用知识 |
| 示例 | `internship-private-notes` | `embodied-ai-journey` |

**工作流**：先在私有仓库写完整版 → 脱敏 → 提炼通用部分 → 推送到公开仓库。两步走，既不耽误记录，也不会泄密。

## commit 规范

commit message 别写 `asdf` 或 `改了点东西`。用这个简单格式：

```
<类型>: <一句话描述>
```

常用类型：

| 类型 | 什么时候用 |
|------|-----------|
| `docs` | 写/改文档 |
| `feat` | 加了新内容 |
| `fix` | 修了错误 |
| `refactor` | 重写/调整结构 |

示例：
```
docs: 新增 RAG 数据处理章节
fix: 修复对比表格中 MPC 描述错误
feat: 添加 VR 遥操管线全景图
```

## 为什么实习一定要有公开仓库

面试官看的不只是你简历上写了「在某公司实习」——他们要看到你能沉淀知识、持续输出、有工程规范意识。

| 没有公开仓库 | 有公开仓库 |
|------------|-----------|
| 「我实习做了 RAG」 | 「这是我在工业场景落地 RAG 的完整记录，这是数据格式、分块策略、评测结果」 |
| 面试官只能听你说 | 面试官能看你的实际产出 |
| 语言描述能力 | 文档 + 代码 + 系统思维的三重证明 |

### 搞一下个人主页

你的个人主页 `github.com/你的用户名` 默认是空的。

建一个和你用户名**完全一样**的仓库 → 勾上 Add a README → 在 README 里写几句话介绍自己：

```
## Hi, I'm keywashion 👋

- 🚗 汽车工程大三 | 🤖 具身智能实习生
- 📖 正在学 LLM、RAG、Agent
- 🎯 目标是懂硬件又懂 AI
- 📂 实习笔记：[链接]
```

保存之后，访问 `github.com/你的用户名` 就能看到这段介绍。

## 以后怎么更新

**加新文件**：Add file → Upload files → 拖进去 → Commit

**改已有文件**：点文件名 → 铅笔图标 ✏️ → 改内容 → Commit

就这两种操作。其他按钮你可能一辈子都用不上。

## 我犯过的错，你别再犯

| 我干的蠢事 | 正确做法 |
|-----------|---------|
| 把公司内部文档直接往上传 | 每次先过一遍安全清单 |
| 仓库名叫 `test123` | 名字是门面，想好再建 |
| README 在网页上改了又改然后冲突了 | 先本地写好，确认 OK 再传 |
| 好几周忘了更新 | 设个周日晚上闹钟提醒自己 |
| commit message 写 `asdf` | 写清楚改了什么，以后自己能看懂 |

---

> 最后一句：别等「完美了再发」。我当时也想等学完一个月再建仓库——幸亏被导师劝住了。
> 一个存在但不完美的仓库，比一个完美但只存在脑子里的仓库，有用一万倍。
>
> 先发出去，再慢慢改。你看到的所有漂亮 GitHub 主页，第一版都是狗屎。没人例外。
